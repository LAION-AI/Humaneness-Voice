What is now available

  • AudioSet event candidates: enabled by default, independently switchable under “Proactive listening & sounds”. Top candidates and a CPU timing card are visible.
  • Sound threshold: 8 dB above the learned room floor. Browser noise suppression/automatic gain are off in Preserve sounds mode; echo cancellation stays on.
  • Music present at startup gets a bounded periodic probe. Sustained sounds collect more context; repeated music comments are suppressed for three minutes.
  • Ask then play: “Was ist das hier?” or “What is that sound?” arms an approximately 2.4-second after-question window. Ordinary questions have no added listening wait.
  • Local reactions OFF by default. When enabled, the short validated reaction sees authorized memory/sound context and its exact text enters Qwen before the main answer starts. Reaction playback overlaps main generation and shared-model TTS. No second filler bridge.
  • Open foreground conversation: no wake phrase required; unknown speakers receive a session label and a name question. A separate quiet-background filter and optional partner focus remain available. Camera and persistent wiki memory remain off by default.

Parallel data flow and bounded delay

Existing microphone → existing ASR / speaker identity
Same microphone → salience + playback guard → GPU Whisper captioner ∥ CPU MN04 candidates
Caption + optional ranked labels / time windows → uncertain observation → authorized conversation context → Qwen → streaming TTS

The two models receive the same captured audio independently. MN04 does not become a required serial gate before Whisper. Its request has a 180-ms deadline; unavailable, overloaded or late hints are dropped. The CPU worker accepts one job at a time and rejects a stale-work queue. The deadline overlaps the caption request; in the unusual case of a faster caption, joining can extend that branch up to the event deadline. Microphone ingress and normal ASR never wait for it.

Labels do not re-prompt Whisper's decoder. They join its caption as a second evidence source for the LLM. A strong music-vs-speech hint can also correct routing. This avoids an extra serial caption pass. Disagreement is passed explicitly as uncertainty, not resolved by treating an uncalibrated score as truth.

Temporal, not spatial: overlapping 1.28-second windows with 0.64-second stride show where a category was suggested. These are coarse classifier windows, not trained event boundaries. A mono microphone cannot supply a reliable left/right angle; spatial localization requires suitable synchronized microphone hardware and another algorithm.

Expanded tests inject deterministic PCM through the actual browser's 20-ms microphone sender, including playback-position tags. The separate music test uses Chrome's fake microphone through the capture worklet. Real model services, hosted/local LLMs and TTS are used. Completion and PCM scheduling do not certify a human listener's physical speakers.

The earlier “text shown but not spoken” bug was premature browser cancellation: raw level/VAD could cancel an optional environmental reply even when the activity was just sound. Environmental replies now ignore that generic browser cancellation source. Server-verified user interruption, Stop and manual controls remain active. The music test injects high level/VAD during a reply and checks that it sends no false avatar:cancel. The UI distinguishes waiting-for-audio, scheduled audio and cancellation.

Speech addressed to Robby versus background

The conservative heuristic requires all three: relative level below 0.28 of the session reference, no confident known-voice match (cosine below 0.62), and no explicit address or self-introduction. With no reference it accepts the speaker. Loudness and estimated SNR alone are not intent classifiers. The filter is independent and can be disabled.

The speaker browser replay covers Christoph, an unfamiliar foreground guest, “Ich bin Selma”, later Selma and quiet unrelated background speech at gain 0.1. A narrow recent-name-answer rule can attach a lower-confidence vocal variant to the just-created unnamed guest, avoiding a duplicate person. This does not guarantee rejection of loud TV or acceptance of every soft user. The protocol defines a held-out voice/level/noise matrix for further threshold search.

The main launcher accepts --with-sound-captions for both sidecars. Use matching PyTorch/torchaudio/torchvision wheels; tested 2.6.0+cu124 / 2.6.0+cu124 / 0.21.0+cu124. Optional event settings: ROBO_EVENT_CACHE, ROBO_EVENT_URL, ROBO_EVENT_PORT. Default loopback port: 8804. Runtime audio is held briefly in RAM and not saved.

The test protocol separates required future scenarios from executed evidence and describes licenses, scene generation, physical-room limitations and controlled threshold searches. Retained failed attempts include a busy public ASR slot, a generic after-question reply and a speaker-name split. They are not silently deleted or reported as passes. The older report is archived here.

Recommended next steps: blind semantic rating on held-out sound mixtures; ablate MN04 vs MN10 on identical clips; music-plus-speech and real singing; loud television versus quiet addressed speech; actual room/echo/device tests. Fine-grained event boundaries or direction-of-arrival would need a separately validated model/hardware path.
