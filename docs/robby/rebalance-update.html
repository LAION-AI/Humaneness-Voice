The short-Stop tradeoff: a fresh clear foreground Stop can cancel speech despite uncertain one-word identity. Strong known-rival and bot-echo checks still apply, and the cue never trains an identity. A loud unknown voice might still cancel. Approximate speaker similarity is not authentication. A lower ordinary threshold cannot separate every pair of voices or repair heavily overlapping ASR.

What the browser really exercises

A fresh CPU Chromium page receives paced 20-ms digital microphone blocks through its actual client method. Recognition, Qwen/Cerebras, TTS, cancellation, reply IDs, audio scheduling and 3-D rendering are real. The script checks quiet TV, a returning voice with changed delivery and multiple distractors, a handover during speech, a full rotation with simultaneous audio, emotion/grimace/nod, live banana-rule interjections, short Stop and recovery, and spoken invite/revoke permissions.

Digital injection bypasses microphone permissions, capture hardware and the acoustic echo path. The browser records scheduled PCM, not measured loudspeaker sound. Stop latency in the receipt starts at input-file capture, including phrase duration and padding; it is not last-word reaction time. A 320-ms controller hop is not a promise of a 320-ms response.

Jokes, follow-ups and complete tasks

The real-model test uses three independent six-turn conversations: robot joke → another → expand the last one → another robot joke at a station → cat joke → another cat joke. Each actual answer becomes the following request's history. The first baseline repeated a whole cat joke verbatim. The revised path distinguishes a new example from a retelling and preserves generated task context after an interruption, explicitly warning that only a prefix may have been heard.

The separate browser sequence supplies no history in its requests: it tests the application's own session memory and actual streamed TTS. Automatic checks cover content, topic, exact repetition and completion; human review is still needed for coherence and a convincing punchline. The full authored dialogues remain inspectable. Why longer stateful tests are necessary

The isolated guest flow passed, but a combined conversation revealed that a previously heard unnamed guest could not receive the later introduced name. The candidate guard had compared the new clip with the best-matching participant, instead of specifically with the inviter. The repair uses the inviter's identity for that guard and reuses the unnamed guest profile. Retained failing combined attempt. Other retained failures included a short Stop rejected despite a correct ASR preview and a harness helper-shadowing error. Harness failures are recorded separately from assistant accuracy.

Audio suites run serially and never evict a real user. Every run gets its own manifest/log/receipt directory. A stale earlier success is rejected; failures are not silently retried. The first search grid is four retention thresholds × three pause settings. Screen with component tests, validate finalists through actual browser conversations, select a recall/false-trigger/latency tradeoff, then freeze it for different held-out voices and rooms. The plan itself does not execute twelve experiments.

Next priorities are command-onset phase sweeps, long TV-only exposure, changing user distance and emotion, measured echo/reverb/jitter, similar voices and multi-person rooms. Count main-turn recall and background-induced replies/aborts together. Preserve complete tasks, participant permissions and post-Stop recovery as hard constraints. Zero false triggers in a tiny test is not proof of a low hourly failure rate.
