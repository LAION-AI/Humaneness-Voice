What the user hears

Memory-aware local reaction → Qwen-informed transition → full Qwen answer

The first local call sees the current request, recent conversation, approximate speaker identity and compact excerpts of the already retrieved wiki entries. It does not see Qwen's answer yet. It can say a tiny grounded answer such as “Deine Freundin heißt Alice” instead of a thinking/waiting announcement. With no matching evidence it must not invent recognition. Current-session self-introductions work even with persistent memory off.

The second local call sees the actual first one or two Qwen sentences, plus the reaction already chosen. It writes a short contextual transition. For jokes only the setup is supplied, so the transition does not receive the punchline. Exact-output tasks and poems bypass both introductions. Invalid, repeated or inappropriate prefaces are skipped rather than replaced by canned filler.

Why parallel text generation alone did not remove the audio gap

Previously the single shared TTS server finished the first utterance before admitting another. Having Qwen's text ready did not make its audio ready. The new internal WebSocket admits independent utterances to one CUDA owner and one set of weights. Global semantic and local acoustic-token decoding share real tensor batches; each utterance retains separate KV and codec state. Codec decoding itself restores one stream's state at a time. Main-answer audio is prefetched immediately, while the second local model call runs.

Two active streams are selected. Three can improve aggregate work while slowing the stream the listener currently needs. That produced early underruns in the retained three-stream runs. The foreground emits a 160-ms first audio block, then 400-ms blocks; the browser starts with a 220-ms reserve. Main utterances retain final forced alignment and fades. Short prefaces use 10-ms fades without alignment holdback. All conversational trials below use TTS temperature 0.8; the isolated deterministic cache test used zero.

Reproduction, evidence and limits

Run the scripts from the published robby/ folder using its pinned stack. The internal TTS transport is loopback-only, shares the existing engine admission lock and does not replace the normal Playground API. No private recordings, credentials or real user memories are published.

python run_unit_checks.py
python benchmark_live_batch.py
python benchmark_two_stage.py --output two-stage-audio-new.json
python benchmark_reaction_memory.py --output two-stage-memory-new.json
python browser_two_stage_check.py --url https://YOUR-DEMO
python browser_two_stage_memory.py --url https://YOUR-DEMO
python browser_two_stage_cancel.py  # edit URL for another deployment

One repeated memory browser run failed before the memory assertion because the existing exact-word TTS path rejected a SCRIPT/transcript mismatch. Its original model wording was not captured, so the cause is not established. The harness now retains all events and surfaces memory errors promptly. A fresh run passed; this does not prove that formatting failure is fixed.

First reaction text remains generated at temperature 0.35; informed-link text at 0.25. TTS is 0.8. One local model is reused, not a second local LLM download. The truncated temperature-zero batching pilot had sample-identical PCM across its tested schedules; that is not a proof of stochastic or perceptual equivalence at 0.8. Some links remain generic or grammatically thin; no human MOS/listening panel was run. Speaker matches and retrieved facts remain fallible. These typed/browser tests do not newly certify acoustic Stop, noisy-room ASR, speaker recognition or universal sub-900-ms latency.
