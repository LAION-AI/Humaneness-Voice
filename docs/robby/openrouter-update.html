Read the timings correctly

  • ASR: the final speech-pause recognition pass. Live preview and the selected pause itself are separate. Alternative recognition includes its loopback request; the native path measures the existing decoder call.
  • Speaker ID: remaining ECAPA/lookup wait on the path to submission. An already prefetched embedding can make this below one millisecond; the background compute time remains visible in details.
  • LLM: time to the first complete sentence or validated tool plan. TTFT and full stream wall time are additional details. Cloud measurements include network transit. Full stream wall time may include downstream queue backpressure.
  • TTS: first decoded/resampled PCM, including server admission and transport. Completed-sentence GPU generation times and RTF are shown separately when supplied by the TTS backend.
  • Reply → first PCM: server response pipeline start to first audio, excluding prior ASR/speaker processing. This is not microphone-to-ear latency.
  • Playback lead: real scheduled audio start minus the browser AudioContext clock. It is a scheduling buffer, not a physical-device latency measurement.

Stages overlap, especially LLM generation and TTS. Do not sum the cards. Each accepted reply has an ID so queued input and late measurements can be distinguished. Existing playback timestamps, interruptions and turn-taking remain in place.

Exact provider routing and tools

The requested web endpoint corresponds to OpenRouter provider tag cerebras/fp16. Requests use provider.only with allow_fallbacks=false; an unavailable provider is reported instead of silently switching. Additional current endpoint tags come from the public model-endpoint API. The model list is allowlisted to Qwen and the local model; arbitrary provider URLs cannot receive the server key.

Reasoning is disabled/excluded for fast spoken replies. Provider-specific unsupported JSON-format parameters are omitted. The same acting catalogue, sentence framer, complete-task guard, avatar commands and tools are shared. Explicit interruption-rule requests require actual tools, preserving the banana-game setup rather than accepting a verbal promise. The independent decision model remains separate. One brief retry handles a rate-limit response before any speech; already emitted words are never replayed. Rate limits and provider outages can still interrupt a request.

Credential handling

The administrator enrolls the key once with python credential_store.py, using a hidden terminal prompt. Authenticated Fernet ciphertext and a separately generated master secret live in a private directory outside the checkout. Directory mode is 0700, file modes 0600. No read-key API exists. The browser sees only credential availability and never receives the administrator's plaintext or ciphertext. Source export and staged release checks exclude credential files.

Optional personal keys use a password field, are cleared on submission and kept encrypted only in that connection's server memory. They neither overwrite the shared administrator key nor enter browser storage. Disconnecting discards the override. Encryption at rest depends on a protected master secret and OS account: this is not an HSM or protection against server-account compromise. Cloud mode sends conversation text to OpenRouter and the chosen provider; audio processing stays on this server and camera inference stays in the browser.

Interface changes

The sticky desktop sidebar shows live ASR, the latest user turn and Robby's current reply. Full history remains available. The six timing cards sit directly under the avatar. Model selectors, microphone/camera controls and the main interruption checkbox stay visible; speech-pause and detailed interruption settings are grouped compactly. Mobile stacks the panels without removing controls. Preferences save model/provider IDs only.
