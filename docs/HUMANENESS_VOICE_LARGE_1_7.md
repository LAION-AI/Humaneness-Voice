# Humaneness Voice Large 1.7

Use [Humaneness Voice Large 1.7](https://huggingface.co/laion/Humaneness-Voice-Large-1.7) for the current standalone Large voice-acting model. It produces expressive speech in English, German, Spanish, French and Dutch. The model release is under CC BY 4.0; retain the upstream notices and the licences of the code and codec dependencies.

The model repository is the source of truth for its weights, inference entry point, training recipe and validation records. This GitHub guide explains how the release relates to the existing agent and serving code. The packaged Playground and Robby defaults remain the separately documented Small RL deployment until an explicit runtime integration is tested.

## Which checkpoint is this?

The lineage is:

```text
Humaneness Voice Large 1.3 Alpha
  → Acting High-8654 full supervised fine-tune
  → rank-32 supervised voice-acting adapter, update 44,250
  → adapter merged at scale 1.0 = Humaneness Voice Large 1.7
```

The selected adapter uses the project's native FP32 `a` / `b` LoRA representation across 146 semantic and local attention modules. It is not a generic PEFT adapter. Its SHA-256 is `5b44fd6e2c6691d391538ec1daa20820cc741e0e09f77910e383babd8c3eb2b6`.

Seven checkpoints from the second half of the adapter run were compared on the same 108 English/German, reference-free tasks: 40 emotions and 14 edge cases in each language. Update 44,250 had the highest mean of the frozen diagnostic: 40% target emotion/style CDF, 30% clipped Content Enjoyment / 10 and 30% clipped genuineness / 6. WER, caps and failures are reported separately. This is development-set selection with one fixed seed, not independent test-set confirmation.

Those selection results were generated by the exact High-8654 BF16 parent with a separate FP32 residual adapter. Merging the adapter in FP32 and then deploying the merged model in BF16 changes rounding, so numerical merge checks do not imply identical sampled tokens or audio. Use the release's merged-versus-unmerged validation records when assessing the merged deployment. Do not relabel the original selection table as a new merged-model evaluation.

The 1.4/1.5 RL continuation and 1.6 RealSpeech rank-4 merge belong to a different branch. Their specialist adapters, scales and evolutionary-search winners are useful research leads, but they are not validated compatibility or performance claims for 1.7.

## Basic prompting

Keep **literal spoken words** separate from the **performance prompt**. The standard performance prompt has two parts:

```text
GENERAL: A warm, spontaneous conversation. The speaker sounds quietly relieved,
with a little amusement and natural hesitation.
SCRIPT:
(quiet, conversational; a hesitant start) [3.2 seconds duration] I thought... you had already left.
(relieved, with a small smile in the voice) [3.6 seconds duration] I'm glad you stayed for a moment.
```

The literal `--text` for this example is:

```text
I thought... you had already left. I'm glad you stayed for a moment.
```

Use English acting directions and the chosen target language for dialogue. Parentheses contain delivery instructions; square brackets describe requested durations. They are directions, not words to read aloud. Keep ellipses where the spoken line should hesitate. Duration instructions are targets, not a guarantee of exact output length. See the [full prompting guide](https://huggingface.co/laion/Humaneness-Voice-Large-1.7/blob/main/PROMPTING.md) for vocal bursts, pauses and additional examples.

## Standalone inference

Download the model repository into a directory and install the CUDA-compatible dependencies described in its README. The following uses its own portable entry point rather than assuming that the older Playground registry already contains 1.7:

```python
from huggingface_hub import snapshot_download

snapshot_download(
    repo_id="laion/Humaneness-Voice-Large-1.7",
    local_dir="Humaneness-Voice-Large-1.7",
)
```

Save the performance prompt above as `performance.txt`, then run from the downloaded model directory:

```bash
python infer.py \
  --language en \
  --text "I thought... you had already left. I'm glad you stayed for a moment." \
  --prompt-file performance.txt \
  --seconds 7 \
  --seed 1701 \
  --cfg 1.0 \
  --output performance.wav
```

The provided baseline uses temperature 1.0, top-p 0.95, top-k 50 and repetition penalty 1.0. It returns full-utterance audio. Twelve MOSS-v2 codebooks represent each 80-ms frame; output audio is 48 kHz. Check the current release CLI before changing runtime flags.

No reference is supplied in the example. Ordinary model inference can also use a clean, single-speaker reference through `--reference-wav`. The release crops the waveform before encoding and validates 63–187 reference frames, approximately 5.04–14.96 seconds. Do not reintroduce the historical 37-frame / 2.96-second truncation.

For CFG above 1.0, supply an explicit matched neutral prompt:

```text
GENERAL: A plain conversational reading.
SCRIPT:
[3.2 seconds duration] I thought... you had already left.
[3.6 seconds duration] I'm glad you stayed for a moment.
```

Save this as `neutral.txt` and add `--cfg 2.5 --neutral-prompt-file neutral.txt` to the command. Keep the same spoken words, timing structure, language and any reference in both branches; remove the acting condition rather than changing the task. Higher CFG is a setting to evaluate, not a universal improvement. The listening comparison contains the relevant controls.

Do not attach the included native adapter again when loading the already merged root model. The separate `--unmerged` path is the release's controlled parent-plus-adapter alternative, not a second adapter to stack on top of 1.7.

## Throughput and streaming

The checked-in [optimization guide](../INFERENCE_OPTIMIZATIONS.md) and [Playground API](PLAYGROUND_API.md) contain useful implementation work. Their scope matters:

| Technique | How to use it for 1.7 |
| --- | --- |
| Load the model and codec once | Keep long-lived instances for repeated requests. Exclude cold loading from warm generation timing, and report both. |
| BF16 merged deployment | Use the release's tested merged path. Inspect its own merged/unmerged checks; merging and casting can change samples. |
| Reuse reference codes | For repeated ordinary inference with the same reference, cache by audio/crop hash, codec revision and quantizer layout. The reference-free manual search does not use this cache. |
| Batch independent candidates | Adapt the native batch/CFG helpers and preserve each request's prompt, length and seed. Measure a safe batch size on the actual GPU. Existing older-Large and Large-RL caps are deployment settings, not 1.7 benchmarks. |
| Stream codec output | The Playground has an incremental transport and stateful codec integration. The release's portable `infer.py` is full-output inference; it does not become a streaming server just because the underlying decoder is causal. |
| CUDA graphs, Triton and fusion | Reuse the implementation ideas after checking compatible shapes, cache state and sampling behavior, then benchmark 1.7. The Jetson Thor Small-model speedups are not measured 1.7 results. |

Record at least the hardware, precision, prompt/output lengths, CFG, batch size, number of candidates, warm/cold state, generation time and codec time. Report aggregate batch throughput separately from per-request latency and time to first audio. A real-time factor measured with EARS/ASR scoring included is not a pure TTS speed measurement.

The repository's 0.16-second onset headline is specifically the Small RL streaming deployment on Jetson Thor. No corresponding Large 1.7 latency or throughput number is implied. See [the release-specific guide](https://huggingface.co/laion/Humaneness-Voice-Large-1.7/blob/main/INFERENCE_OPTIMIZATIONS.md) for available measurements and pending experiments.

## New prompting manual search

The new three-generation evolutionary recipe search is a preparation plan, not a completed manual or a submitted search job. Its contract is **reference-free throughout**: no reference audio during candidate generation, CFG branches, seed/script holdouts or final validation. The existing fixed-reference showcase is a separate listening study and cannot establish a reference-free winning recipe.

The search plan preserves every candidate, not only winners: audio and codec tokens, complete conditional and neutral prompts, CFG, temperature and other sampling settings, seeds, model identity, mutation lineage, raw judging results, failures and rejection reasons. This enables a later HTML manual to show the winning settings and the evidence behind them without hiding unsuccessful attempts.
