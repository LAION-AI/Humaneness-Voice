TTFT means first text token. First audio means the first playable PCM packet received, not the end of the spoken reply. Full generation is the time to finish generating all audio, not its playback duration. Warm steady-state samples use an already loaded model. Raw rows include actual input and output word counts, failures and per-sentence metrics.

“ASR + LLM + TTS (offline audio)” sends a complete prerecorded synthetic request to ASR, then its recognized text to the real LLM/TTS path. It excludes speaking duration, streaming endpoint detection, microphone hardware and browser/device/network buffering. A separately documented real-time browser/socket test measures that additional path; these numbers must not be presented as microphone-to-speaker latency.

Pipeline and choices

Stable ASR sentences are labelled using nearest full-utterance ECAPA voice prototypes. Unknown speakers are answered, numbered and optionally asked their name. Explicit self-identification can attach several acoustic prototypes to the same session person. The LLM outputs short acting cues and spoken words; 100 fixed GENERAL templates are matched in memory. A completed output sentence immediately enters streaming TTS while the remaining LLM output continues. New input sentences queue in order and enter the next LLM request with conversation history. Already decoding LLM requests cannot be retroactively edited.

The report compares 160, 400, 800 and 1600 ms requested TTS frame chunks (2, 5, 10, 20 frames). Actual MP3/PCM packet lengths can differ because of codec and final-tail boundaries. Smaller chunks may reduce first audio at the cost of more decoding/transport work. See the measured rows before choosing a default.
