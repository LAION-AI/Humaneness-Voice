How to use it

Reload an old tab (Ctrl+Shift+R), press Start talking and grant microphone access. Say “Hey Robbie, ich bin Christoph” or “Hey Robby, I am Christoph”, preferably as one complete sentence. Each new person introduces themselves the same way. Subsequent speech is matched against session references and the answer addresses the current speaker by name. After about one second without that person's voice, their turn closes even if the quieter background keeps talking. Wake-only enrollment gets a short 2.5-second grace for a following introduction. Talk without speaker filter explicitly bypasses identity gating; typed messages also bypass enrollment.

The microphone panel distinguishes local capture, server receipt, ASR preview and accepted turns. A visible preview is deliberately not proof of submission: ambiguous or unrelated speech must not trigger a reply. Clear or disconnect forgets enrolled voices. One live browser session is supported; several people can share it.

What was fixed

  • Existing suspended browser audio contexts resume when microphone capture begins. Cancelled startup, late permissions and stale socket events cannot leave a microphone attached or stop a newer session.
  • Speaker-owned one-second clocks replace room-wide silence for the filtered mode. Silence does not refresh a person's clock merely because a diarizer channel remains bound. Diarizer channels are reusable activity tracks, never permanent identity labels.
  • Chronological pre-roll preserves clipped wake words. Independently cropped owned-word ASR must agree with raw sentence views; a nonverbal foreground cannot borrow background-TV words. Teacher embeddings use full and ASR-trimmed acoustic views, not an accidentally shortened reference. Async identity corrections rebind open continuations atomically.
  • Only native TYGER/second-ear interruption proposals stop playback; enrollment gates them and can replay a recent proposal after speaker verification. No speaker-activity-only bypass can turn bot echo into an interruption.
  • DAC position, capture timestamps, playback gaps/cancellation and explicit latency estimates drive the second-ear reference. Software clock results are not a claim of zero physical-device error.

Current latency update

The latest path uses monotonic native timestamps to bridge delayed diarizer rows and time-aligned native enrollment centroids. Observed background channels establish a relative 2x-amplitude foreground guard, so quiet matching background cannot renew/reassign a user clock. Actual DAC-aligned playback-waveform evidence complements the timbre-based echo competitor; native BARGE proposals and full known-user checks are still mandatory. Shared encoder calls are serialized defensively, and fatal CUDA-worker failures now report not ready rather than appearing microphone-ready. Physical microphone/room validation remains outstanding.

Up to three frozen enrollment templates (2, 3.04 and 4 s) capture phonetic variation in the same verified introduction. Scores use the best template per identity; margins remain against other people. The new report includes duration and background-impostor checks and their limited synthetic scope. A high-energy candidate is no longer marked as background merely for missing a wake or having too little embedding context.

The current live path uses one compact Luna call, prepares ASR/identity during the pause and validates name metadata locally. Speaker models and completed research

The frozen Nemotron ASR encoder supplies live hidden states, so speaker prediction does not run a second encoder. The fast V4 Query-GRU mixes layers 4/8/12/15 (one-based), has 648,071 trainable parameters and pools four 80-ms frames. Its matched synthetic test identification/EER is 71.07%/14.28%, versus 67.38%/15.48% for the baseline. The completed V5 duration study ran 45 jobs; its selected utterance-target recipe reaches 70.63%/14.25% at 2,000 ms and 71.05%/14.18% at 3,040 ms. The three-second identification advantage is only +0.43 pp (identity-bootstrap interval −0.28 to +1.07 pp). Live fast cues use V4; longer references now default to completed V5 three-second features, with the two-second option available; no extra waiting is added to collect a full window.

Both studies use 480/10/10 synthetic voice identities with no split overlap, but reuse earlier benchmark test identities. The 320-ms figure is a pooling/output interval with causal encoder history, not a cold-start 320-ms-only guarantee. Full-utterance frozen ECAPA verification complements, rather than magically fixes, the student. Default full-utterance cosine is 0.50 with nearest-reference margin 0.08; conservative bounded continuity relaxation is documented in the README. These are prototype operating points, not security calibration.

3D design and animation

The browser prototype follows the supplied desk-robot proposal: 190-mm white head, 150-mm round display bezel with 127.6-mm active area, top camera opening, side caps, pan/tilt neck and 220×70-mm base; nominal height 315 mm. There are no arms, chest heart or cross. Original lightweight procedural surfaces replace a supplied 1.89-million-triangle mesh. Canvas 2D projects/depth-sorts 2,788 quads, without WebGL, CDN or mesh download. Pan is limited to ±90°, tilt to ±15°, and roll is disabled. The head has optional local face-following; orbit, manual controls and an exploded inspection view are available.

Both avatars reuse the same Luna/ASR/TTS pipeline and 40 authored emotion poses. Luna's explicit sentence-level TTS acting instructions drive the face; microphone volume does not classify emotion. Actual playback positions anchor the animation, but sentence boundaries remain prompt-derived estimates rather than forced alignment. Fake-camera startup was tested; real gaze-tracking accuracy was not measured. This is a visual prototype, not manufacturing CAD, collision checking or servo control.

Interruption operating point and latency

The original frozen native GRU remains the source of interruption proposals. Filtered mode uses its supported sensitive setting (yield threshold 0.20, one-frame debounce), but every proposal must pass full ECAPA matching against enrolled users and the actual streamed bot voice. Default cosine is 0.50 with margin 0.08 against other users and bot playback. Strong native proposals (yield ≥0.8) can retain a recent, independently fast-matched known track using the bounded continuity floor max(0.42, threshold −0.08) and margin ≥0.12. There is no enrollment or speaker-activity-only bypass. Unfiltered mode restores the original native settings. The actual streamed-echo test initially lost an Idris interruption; the more sensitive, acoustically guarded operating point corrected it. Its first successful interruption took about 2.8 seconds. A 320-ms prediction interval is not a promise of 320-ms identity-confirmed interruption latency.

A medium short-window speaker cosine alone is insufficient: ordinary confirmation also requires recent independently diarized ownership. A previously unseen channel needs a substantially stronger known-reference match (cosine ≥0.70, margin ≥0.20). This guards background male voices that can otherwise obtain misleading short ECAPA scores. No new identity is enrolled by this exception.

For close known voices, full/cropped consensus permits a smaller 0.04 nearest-user margin only with cosine ≥max(0.55, configured threshold), ≥0.90 acoustic agreement, ≥1.5 s voiced and ≥0.12 separation from playback. Close-score decisions cannot update the reference. New self-introductions always use the original full identity span, even when the diarizer reused another person’s channel. Shifted acoustic views are compared by their samples, not merely their lengths.

A low-energy background candidate cannot activate using a louder person’s greeting, even if its clipped ASR invents a full introduction. Eligible new foreground tracks may independently re-decode up to 1.6 s of preceding original audio to verify a real same-name greeting across a channel transition. No wake text is fabricated. When independently owned-word recognition verifies a substantial ASR prefix trim and at least 1.28 s remains, identity combines 80% crop and 20% whole-span embeddings; otherwise the weights are equal. Ordinary views require cosine 0.50. Only an independently proven quiet other-voice prefix allows 0.35, with full retained-speaker matching, no worse owned-word transcript agreement and the original view retained at 20% weight. Divergent views cannot adapt the original reference. This avoids giving discarded TV pre-roll equal weight without removing the whole-span check.

For a near-tied teacher winner, the separately calibrated Nemotron student can corroborate that same known person: fast centered cosine ≥max(0.70, fast threshold), combined margin ≥0.10, full ECAPA above threshold, ≥0.85 acoustic-view agreement, ≥1.28 s voiced, and ≥0.12 separation from bot playback. The student cannot overrule a different teacher winner or enroll an unknown voice through this path. Close-score corroboration never adapts the reference; disagreement requests repetition.

When bounded prefix crops retain exactly the same independently verified word sequence, the latest such crop avoids unnecessary TV pre-roll. The background-suffix guard tolerates one ASR insertion/deletion in the best matching owned prefix, such as a dropped article, while still permitting one quiet missing final word. A multiword unowned TV suffix cannot bypass the guard merely because one article differs.

Sentence boundaries and reference stability

Up to 800 ms of already-received post-roll preserves quiet word endings without adding a second endpoint timer. Identity enrollment excludes this trailing room audio. Independent owned/raw recognition rejects ambiguous text; a multiword TV suffix after an independently recognized sentence is discarded. This remains a conservative heuristic, not true source separation.

Timestamped, same-name wake evidence can recover a greeting clipped by the diarizer. Incremental name guesses are provisional and can be corrected by the completed introduction without orphan profiles; the UI says joining… until a full reference exists. Two sufficiently long, acoustically agreeing and separated follow-up embeddings may form a small bounded centroid, weighted at half the original introduction anchor. The anchor is immutable, updates cannot recursively drift it, and actual playback is also a competitor at full-turn verification. All identity memory remains session RAM.

Shared-model admission and cancellation

A cancelled shared TTS request may remain busy briefly. The bridge now waits up to 45 seconds with visible waiting/preparing status and supports Stop throughout. Explicit HTTP 409/503 responses are retried only before admission. An accepted stream or ambiguous network failure is never retried, preventing duplicate speech. Other Playground requests are never evicted. Newly confirmed enrolled speech can cancel a pending reply before audio arrives; evidence starts after reply submission, so a preceding utterance cannot cancel its own answer.

Observed host GPU incident

A separate failed run accepted six named turns and then lost the native ASR GPU during interruption testing. NVIDIA kernel locks and nvidia-smi were observed stalled while ordinary HTTP health still answered. The five-second microphone-backlog guard closed the call. After the driver responded again, only the owned Robby worker was restarted; no shared GPU reset, host reboot or termination of unrelated jobs was performed. The failed run was not counted as a pass. The final receipt above is a subsequent rerun. Application fixes cannot guarantee availability during a shared-host driver stall; the UI now explains the backlog/reconnect error.

Limitations and privacy

Real rooms, loud simultaneous speakers, distant microphones and very short utterances remain uncertain. Diarization is not source separation; the safe response to an unresolved mixture is to request repetition, not confidently invent a speaker. The synthetic test passing does not establish real-person accuracy or secure identification. Test fixtures are synthetic and a malformed Selma fixture was explicitly retained as a nonverbal rejection case rather than counted as an intelligible turn.

Raw microphone audio and enrolled speaker references stay in session RAM; names and words also follow the configured Luna API and shared Playground temporary-output policy. The server sends recognized text to the configured Luna API and uses the existing Playground's temporary synthesized-output storage. No private recordings or enrolled voiceprints are in the source/model release. Camera frames stay in the browser. Public synthetic test traces are opt-in on loopback only, never enabled through Cloudflare. User-supplied design PDFs/images/mesh are not redistributed or relicensed.
