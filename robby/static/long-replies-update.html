Open Robby · Source and setup

Complete poems, longer answers and a warmer robot

Robby now completes requested creative work and detailed answers instead of reducing them to a short conversational acknowledgment. Its personality is warm, playful and emotionally expressive in character. Sentence-level TTS streaming is retained; the first line can play while the rest is generated.

What caused the problem?

  1. The released GGUF template appends “Respond as briefly as possible” when conversational_mode is true. It was enabled in addition to our own short-response guidance.
  2. The ordinary director allowed only 320 output tokens. The tool fallback had a separate 120-word validation ceiling.
  3. The stream parser expected full-stop sentence boundaries and could not correctly handle verse lines without punctuation or preserve their display formatting.
  4. Generic negation such as “Keine Einleitung” could incorrectly route a poem into the interruption-rule tool path. That path also collapsed line breaks.

Production timing logs and runtime code were inspected. They do not store the user's full private transcript, so this report does not pretend to reproduce the exact last human conversation. The examples below are newly authored regression prompts.

Implemented changes

The local prompt prioritizes completing the actual task, respects requested structure and supports playful simulated emotions without repetitive disclaimers. conversational_mode is disabled while thinking stays disabled. Ordinary output has a 2,048-token ceiling; deliberately tiny benchmarks/avatar reactions remain bounded separately. Recent history is kept in order with a context budget.

Poetry uses complete verse lines; prose uses sentences or bounded phrases. Acting cues stay out of spoken text. Newlines and stanza breaks remain in the UI and history. The reply language is retained across individual lines. For counted poems/stories, a structure guard can request just the missing continuation at most twice; it does not replace earlier speech with a canned answer. A pilot that stopped at six of eight lines motivated this guard. The UI marks an actual response limit if completion still fails.

Scope and limits

These are real local-model and browser/TTS checks with synthetic authored requests, not a human evaluation of literary quality. Structural completion does not guarantee perfect rhyme, grammar, factual accuracy or instruction following. The small local model can still produce awkward wording. Responses remain bounded by available context/output tokens; the guard is bounded, not an infinite retry loop. Real-room microphone behavior is covered separately by the speech-pause report; this browser check uses typed requests and actual audio playback.

The source contains the exact local prompt, compact tool recipe, counted-task planner, stream parser and validation scripts. No private microphone recordings, voiceprints or human conversation transcripts are included.
