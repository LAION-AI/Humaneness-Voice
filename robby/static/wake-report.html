Hey Robby mode

Open live demo · Implementation and reproduction · Test protocol

Default behavior

Say “Hey Robby” and your request. Your voice can continue without another wake phrase for ten seconds; the window is renewed after Robby finishes an answer. A different or uncertain voice needs its own wake phrase. Recognition is approximate; it is not authentication.

Speech-pause default: 300 ms, adjustable. That is not total response latency and may split a sentence. Automatic sound reactions default off. Explicit sound questions still use the short RAM buffer and an after-question window; captions can be wrong.

Limits and previous failures

Earlier attempts are preserved below. A 300-ms pause split an introduction into two answers, and an earlier version let the ten-second window expire while Robby was still replying. The current version permits the same voice during playback and renews the window after playback ends. Earlier tests also exposed a sound buffer that was too short and a voice embedding distorted by preceding music; the bounded buffer and tail-window verification were revised. Compare source fingerprints rather than treating earlier failures as current results.

The second-speaker introduction may also contain an ignored short continuation even when its first wake turn succeeds. Open mode can admit the returning speaker under an unnamed label; a direct identity question now asks for the name instead of guessing a previous person's name. A case labelled PASS for mode switching does not prove every speaker label or every fragment was correct. These few clips do not establish performance with real users, simultaneous voices, a television, echoed playback, short Stop commands or similar voices. False accepts and missed matches remain possible; the mode is not a biometric security boundary. If recognition is uncertain, repeat the wake phrase or disable the mode.
