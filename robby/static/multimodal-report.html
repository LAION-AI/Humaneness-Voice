How to use it

  1. Turn Camera on and Start talking. Introduce yourself: “Hey Robby, ich bin Bob” or “Hi Robby, my name is Alice”.
  2. Keep one clearly speaking face visible during introduction. The verified voice and face receive a common person ID only when the visual match is unambiguous.
  3. The three visible-speaker checkboxes are independently enabled by default and remembered in this browser.
  4. Camera off/unavailable deliberately falls back to the previous audio-only behavior. Camera ON with no visible speaking person or ambiguous overlap abstains. Turn Ignore offscreen speakers off to retain audio-only eligibility with the camera on.
  5. Face and voice profiles are session-only unless EVERY affected person has explicitly consented to storage. Remember prompts for confirmation; withdrawal removes saved profiles. Forget all clears both browser and active server speaker memory.

Architecture and models

Existing webcam → MediaPipe Face Landmarker 0.10.21 CPU/WASM worker → stable bounding-box tracks and normalized lip/jaw motion over 700 ms → microphone-sample-clock matching → existing acoustic gate → unchanged Luna and shared Humaneness speech model. Audio-correlated speaker position feeds the existing smoothed gaze controller. Face descriptors use a second lazy worker with only face-api.js 0.22.2 recognition net (128 dimensions; 6,444,032 bytes of weight shards). No second camera, face detector, landmark model, age/gender model or server GPU pipeline is added.

Time-varying normalized lip distances must change direction repeatedly; a static open mouth, closed mouth and rigid translation/scale fail the activity tests. Confidence hysteresis, 380-ms minimum observation span, brief-loss grace, crossing ambiguity and gaze-switch dwell reduce jitter. Face descriptor Euclidean distance <0.48 and runner-up gap >0.08 are development thresholds, not probability estimates.

Human was inspected, including its model catalog and descriptor code; the standalone face-api recognition API was simpler to isolate without attribute inference. This is not a benchmark proving superiority to every Human variant. VSDLM and ONNX Runtime were reviewed but not added: another mouth-state classifier is not needed for the current landmark-first implementation. Comparative VSDLM/real-room accuracy remains unmeasured.

Privacy, limits and remaining validation

Face images, landmarks and descriptors stay in browser memory. The server receives bounded temporary track IDs, activity scores and capture times, not images. The visible people gallery shows the original enrollment crop separately from the current camera crop; old profiles with no photo explicitly say so. Consented name/face/audio profiles are stored unencrypted on this device only; default persistence is OFF. A new person pauses saving until consent is renewed. No private microphone/camera material or enrolled voiceprints is published.

Up to four visible faces and eight enrolled people are supported. Chewing, repeated non-speech mouth motion, occlusion, poor light, tiny/sideways faces, crossed tracks and overlapping speech can be uncertain; the system abstains rather than enforcing an identity. Merely seeing a known face does not authorize audio: the separate corroborated interjection route still needs teacher, fast and long evidence. Gaze calibration remains perceptual, not a camera geometry calibration. Webcam input latency may be incompletely reported; ±160 ms is a matching tolerance, not physically measured synchronization accuracy. Camera-unavailable fallback is explicitly displayed.

Historical short-word interruption identity and arbitrary semantic interruption rules still have retained failure cases in the full worklog. Passing this multimodal test does not turn those older open research items into verified successes.
