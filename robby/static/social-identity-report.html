Better continuity without accepting every voice

Open matching defaults to cosine 0.32. A recent named last speaker can remain a tentative match down to max(0.24, threshold − 0.08), only within 60 seconds and with at least a 0.08 lead over other voices. Such weak matches never add prototypes. Strong different voices and explicit name corrections retain their separate meaning.

A person can have up to eight ECAPA prototypes. Explicit corrections can add another vocal mode; strong automatic additions require 0.55 cosine and a 0.12 rival margin. Name questions have 90-second per-person and 45-second global cooldowns. These are heuristic thresholds, not identity probabilities or secure authentication.

Profiles, memory and controls

Uncertain vocal age/gender and timbre impressions are ON by default. The existing GPU Humaneness Ears model describes perceived register, brightness, resonance, warmth and related vocal qualities. Up to twelve accepted observations form a tentative profile. These are audible impressions, not someone's actual age, gender identity or personality. They never decide who a person is.

The lower People Robby knows · voice profiles panel shows names, prototype counts and traits. Optional browser persistence requires everyone's permission and is OFF by default. It saves approved named profiles locally; new visitors remain session-only until consent is renewed. Embeddings are never sent to Qwen. Turning it off removes that voice store; Forget all clears face/voice profiles. Separately consented face storage can be managed in Recognition & privacy settings.

Facts, relationships and interests use the existing separate, default-off wiki memory. Vocal guesses are not promoted to facts. Forgetting biometric profiles does not silently delete that wiki; it has its own reset.

Camera: available, but still opt-in

Camera auto-start, webcam Face ID and face-VAD gating remain OFF by default. Enable the camera and webcam Face ID to use optional face/voice association. Following position is independent. A missing connection between visual identity and the newer sentence pipeline is now restored: an unambiguous time-aligned speaking face can bind to its named voice, without requiring camera-gated speech.

Existing MediaPipe landmarks and face-api embeddings run in CPU browser workers. The test detected two public-image faces and produced repeatable 128-D descriptors. It also rejected a held-open mouth, static mouth, jitter and rigid head movement as speaking evidence. This is not a human webcam identification study.

Curiosity that waits its turn

Prominent sounds and unfamiliar audible-voice questions are on by default. Quiet-background filtering remains independent. Two sufficiently audible rejected background segments within 25 seconds can prompt one tentative question; 120-second cooldown, playback guards, user permissions and idle scheduling prevent repeated intrusion. This does not enroll the background voice or transfer conversation ownership.

Prompting alone still produced one irrelevant greeting in five probes. The optional voice question now waits for a relevant-question check before TTS. A bad draft gets at most one regeneration; if both fail, that optional comment stays silent. Only the first matching question is spoken. This narrow lexical guard is not a general semantic truth checker.

Sound hypotheses explicitly allow a television, a recording, another person, or the same person speaking differently. The GPU captioner and CPU AudioSet candidates continue alongside ASR; no extra model blocks an ordinary foreground turn.
