What changed

Capture and playback share one AudioContext. Each 20-ms microphone block carries the exact reply ID and 24-kHz playback sample position corresponding to its capture timestamp. Output position comes from getOutputTimestamp(), with reported device latency as an explicit fallback; input latency is used when available. Network arrival time is never the synchronization clock. Scheduled gaps remain silence, cancelled future audio is removed, and already played history is retained for delayed capture blocks. Completion waits for browser DAC playback, not TTS generation completion.

The server reconstructs its second ear from the PCM actually delivered to the browser, using one stateful polyphase resampler. The original TYGER turn-taking heads, debounce rules and thresholds are unchanged. A user-triggered quiet chirp can estimate additional acoustic delay by correlation; weak or AEC-suppressed echoes yield “uncertain,” not an invented correction.

Scope and limitations

The model check used two existing synthetic TTS utterances, not private microphone recordings. Echo scaling was −26 to −90 dB, with an artificial 400-ms reference lead in the control. Repeated BARGE events are counted in the diagnostic continuous-speaking replay; live playback stops at the first event. These are four controlled echo conditions, not a population benchmark. An earlier, discarded diagnostic paired a short reply with a long speaking-mode silence; it is not included as evidence. Room reverb, Bluetooth clock drift and each browser's true input latency still require physical testing. Headphones remain useful when acoustic echo cancellation is ineffective.

Seven correlation tests recovered synthetic 0–440-ms delays and rejected silence/unrelated noise. Twelve upstream second-ear tests passed. Responsive desktop/mobile checks found no horizontal overflow or JavaScript errors. Camera processing is local; no microphone audio or voiceprints are published.
