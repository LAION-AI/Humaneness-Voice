gpu-unlock and the local Nemotron E4B

October 26, 2026 · actual source checks, host compilation and local inference measurements.

No unlock speedup was measured. Both RTX 3090 GPUs have a supported device ID, but this pinned module fails to compile on the host's Linux 5.4 kernel. Its early-boot/reset mechanism cannot be tested safely as a per-process change beside the running demo. The benchmark below uses the existing, unchanged local LLM.

Why the actual intervention remains untested

The upstream module changes Ampere instruction-rate selectors before the stock driver attaches and performs a PCIe function reset. It skips an already bound device. Its primary expected benefit is floating-point matrix/prompt processing, rather than an equivalent improvement to quantized serial token generation. See the pinned upstream explanation, device/driver checks and selector/reset code.

Inference for this application: benchmark Q4 prefill and decode separately. Dense-BF16 GEMM gains do not establish a Q4 assistant speedup. First obtain an uncontended baseline; after arranging maintenance, compare on the same compatible kernel, driver, exact model, clocks, thermal state and prompts with only the unlock condition changed. A kernel upgrade between conditions would confound the result.
