Decision: keep Luna as the production default. DeepSeek passed the same checks but was slower here. Mercury, Gemini and the tested local Gemmas were often faster, but failed important instruction/tool checks. A claim that an interruption rule was installed is not equivalent to executing its real tool. These results describe our gateway, prompt and parser—not a claim that a vendor model is fundamentally incapable of tool use.

Fourteen explicit tasks cover German/English, exact words, arithmetic, two-sentence stories, speaker labels, context, honest tool limitations and installing/cancelling real interruption rules. Three repetitions per API model and Gemma 12B; two for E4B. Every failure counts, including invalid JSON. Luna/Mercury/DeepSeek were serially interleaved with rotated order. Gemini, local models and the Mercury adaptation were later sessions, not simultaneous matched-load experiments. Timing includes HTTP, full director output, validated tool round-trip and bounded existing provider retries. It is not token throughput, TTFT, ASR latency or time to audible speech. This small explicit-check set is not a broad human quality evaluation.

API models used the already configured Hyprlab gateway; direct native vendor endpoints were not tested. Mercury additionally used its documented instant effort, a strict three-field JSON schema and a 2,048-token output budget. Baseline used the existing none effort/900-token JSON-object request. No real session rules were changed by the synthetic model tests.

Local Gemma feasibility

Gemma 4 E4B and 12B instruction models, official QAT Q4_0 GGUFs, text only. Both loaded and generated on this RTX 3090 server, using GPU 0 only, one at a time. Runtime: llama.cpp 5d9e5ac; 8,192 context, one slot, 99 GPU layers requested, 8 threads, batch/ubatch 256, flash attention on, reasoning off. No multimodal projector. These shared-machine tests do not establish performance under simultaneous heavy ASR load. Temporary LLM servers are stopped; neither replaces the shared TTS model.

Wake-free speakers and explicit voice variants

The new checkbox defaults ON. Known-reference recovery runs first; sufficiently long, coherent, dominant new foreground speech can join as a temporary Guest without “Hey Robbie”. Robby answers and asks a name once. “My name is Alice” names a guest. “It’s me, Bob” / “Ich bin’s doch, Bob”, in a clear longer sentence, explicitly attaches an unnamed guest’s new fast/long/ECAPA anchor to one existing unambiguous name. Up to four separate variants preserve the original anchor. Two named people are not automatically merged. The UI displays variant counts.

These are user-asserted conversational labels, not authentication; another person can impersonate a spoken claim. Open enrollment can also admit dominant TV/background speech. Switch OFF to restore wake-required new enrollment. Overlap, final word-origin, ECAPA and playback-echo checks remain. All new anchors are session RAM only, expiring/clearing with the person; no new biometric persistence. Face VAD/Face ID remain OFF by default, with camera gaze independent.

Public information tools

News: official RSS from Tagesschau, BBC, Deutsche Welle, Deutschlandfunk and The Guardian, fetched concurrently. Topic matching covers recent feed entries, not the complete web. Weather: Open-Meteo geocoding plus current/three-day forecasts, explicit location, dates, units and WMO descriptions. A guessed location is blocked before HTTP. Wikipedia: German/English MediaWiki search and short extracts. Actual links appear under “Sources consulted”; this does not guarantee every generated claim is grounded.

Bounded allowlisted HTTPS GETs, checked redirects, 1.5-MB responses, 6-second per-request/10-second per-tool budgets, strict arguments and one bounded tool round. Public-result cache: 128 entries, three minutes, or ten for weather. No voiceprints/audio/history is sent to sources. Model summaries still need fact checking for consequential decisions. Open-Meteo’s free hosted API is non-commercial; publisher feed terms and Wikipedia attribution/CC BY-SA apply.

Additional regressions: 11 microphone/playback lifecycle checks passed; camera/follow controls, stable face tracking, reference images, independent voice/face status, privacy opt-out and persisted settings: True. These use fake browser devices and deterministic landmarks, not a physical camera.

Retained development failures: first Wikipedia request lacked an acceptable identifying user agent; first guest responses omitted the name question; a first weather test guessed Berlin despite no user location. The latter two now have explicit code guards. First variant replay was attempted while ASR was starting (HTTP 503); the test now waits for readiness. A later replay exposed an old known-person veto against a second qualified new guest. Another lost the explicit claim prefix at a diarization-channel boundary. Prefix recovery now requires independent transcription and agreement between two non-overlapping acoustic windows, and never bypasses overlap masking. The variant test intentionally asserts one name from two different synthetic voices, then repeats the same claim clip and tests the original voice with different words. It tests session association and anchor retention, not held-out accuracy. Real-room accuracy and language/emotion generalization of the new variants are not established by synthetic tests.
