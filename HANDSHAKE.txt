1. PURPOSE AND CURRENT STATE

This machine runs an interactive German-first voice assistant called Robby:
browser avatar / 3D desk robot, streaming speech recognition, approximate
speaker identity, conversation and tools, Humaneness Voice TTS, optional
environmental listening, facial tracking and local wiki-style memory.
The user values a responsive, warm, playful conversation, reliable stop /
interrupt handling, usable speaker continuity in TV/noisy environments, and
transparent reproducible tests. Keep previous capabilities and user choices.

4. CURRENT SETTINGS AND DATA FLOW

Current main LLM: qwen/qwen3.8-27b via OpenRouter, Cerebras FP16 endpoint
when the server credential is configured; local Nemotron Bolt E4B is another
selectable backend and may become the fallback default without a credential.
Provider choices and exact active source are visible in the UI. Hosted LLMs
receive relevant conversation text and authorized context; they do not receive
raw speaker embedding vectors or face photos.

ASR: Parakeet TDT v3 final by default; Nemotron 3.5 streaming previews and
TYGER features/turn decisions remain in use. Alternatives, including German
Moonshine, Nemotron telephony and Whisper Turbo, are in asr_catalog.py.
The pause setting defaults to 700 ms and is user adjustable. Voice identity
uses existing SpeechBrain ECAPA 192-D prototypes; open-speaker threshold is
0.32 by default. A narrowly bounded recent-person continuity rule may report
uncertainty and must not train on a weak match. Multiple voice variants per
person and explicit name corrections are supported. Focus uses separate
controls; do not silently conflate the focus threshold with open-speaker 0.32.

TTS: Humaneness Voice Small 1.1 Alpha RL r128 v1, pinned model and launch
details in README/restore inventory and humaneness-small/. Current normal
speech generation passes temperature 0.8 and guidance 2.0; the normal chunk
default is 20 semantic frames (approximately 1.6 s). Optional quick reaction
uses shorter chunks; it is OFF by default. Verify runtime env and selected
voice/profile rather than assuming every historical TTS study setting is live.

Proactive sounds / unfamiliar audible voices are enabled by default, with an
8-dB prominence default, playback protection, cooldowns and uncertainty.
Whisper sound captions run alongside CPU EfficientAT candidates. Ears Medium
voice-delivery and uncertain vocal age/gender/timbre hints run on GPU and are
ON by default. They are approximate audible impressions, not facts, speaker
authentication or reliable demographic identification. The optional background
question is checked before TTS; one invalid draft may be regenerated, and a
second invalid draft is suppressed. Normal foreground streaming is not held
by this check.

Camera auto-start, face-ID and face-VAD filtering are OFF by default; face
position following is available when a user enables their camera. Face ID can
optionally associate an unambiguous visible speaking face with voice identity.
Persistent biometric profile storage is explicitly consented and OFF by
default; browser storage is unencrypted. The separate factual wiki memory is
also OFF by default and has its own settings/reset. Browser-saved preferences
can override defaults. Never publish private microphone recordings, camera
images, biometric vectors, wiki contents, personal settings or credentials.

7. IMPORTANT OPEN FOLLOW-UPS

No new development task is implied merely by this handover. If asked to improve
the system, start from actual current user observations and reproduce failures.
The most important remaining validation is with consenting held-out humans and
real microphones/webcams: varied emotions/languages, same-person variants,
similar voices, quiet addressed speech with TV/music, simultaneous speakers,
false matches, duplicate profiles, unsolicited background questions, stop /
interrupt timing, echo and ASR word loss. Measure both false accepts and misses;
do not just lower thresholds or claim perfect reliability. Check whether the
user has enabled camera or persistent memory before diagnosing those features.

Recheck proactive-question relevance and actual audible output (not just that
text was generated), preserve failed cases, and separate routing/lexical checks
from real semantic quality. Maintain the test protocol and report as findings
change. Keep the demo responsive and prioritize the current speaker; respect
requests to ignore background audio. For experiments, use non-disruptive CPU
or available GPU capacity, bounded disk storage and reproducible seeds/config.
